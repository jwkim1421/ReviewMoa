## 사이트별 승인 절차

1. 리뷰가 많은 상품, 적은 상품, 없는 상품을 각각 3개 이상 선정한다.
2. 비로그인 상태에서 상품명·리뷰 개수·별점·날짜·본문을 확인한다.
3. 최신순과 별점 1~5 필터가 실제로 적용되는지 확인한다.
4. 로그인이 필요한 경우 사용자가 로그인한 뒤 동일 작업이 재개되는지 확인한다.
5. 리뷰 없음과 리뷰 영역 탐색 실패가 서로 다른 상태로 반환되는지 확인한다.
6. 각 사이트 최소 10개 상품에서 오수집이 없을 때만 `verified`로 전환한다.

CAPTCHA 풀이 자동화, 접근 제한 회피, 프록시·계정 순환은 검증 방법에 포함하지 않는다.

## 네이버 canary 기록

### 2026-07-29

- `brand.naver.com/baseus/products/11664146541`
  - 일반 Chrome에서 정상 표시
  - collector 전용 Chrome에서도 접근 제한과 CAPTCHA 없음
  - `data-shp-contents-type="review"`와 고유 `data-shp-contents-id` 확인
  - 상단 대표 리뷰 12개의 별점·본문·ID 추출 성공
  - 전체 6,003건 목록은 자동으로 열리지 않아 `summary_only`로 표시
  - 공개된 대표 리뷰 12개는 버리지 않고 정리하되 작업 상태는 `partial`로 처리
  - 보고서에 전체 목록을 열지 못했다는 제한과 리뷰 수가 충분하지 않다는 안내를 표시
- `search.shopping.naver.com/catalog/53509411418`
  - 일반 Chrome에서 정상 표시
  - collector 전용 Chrome에서는 첫 접근에 `access_blocked`
  - 추가 재시도와 우회 없이 즉시 중단

현재 결과는 네이버 전체가 차단된 것이 아니라 호스트와 페이지 유형에 따라 접근성이
다름을 보여준다. 10개 검증은 브랜드/스마트스토어 상세와 가격비교 카탈로그를 분리해
기록한다.

  - 네이버 원본 리뷰 443개와 별점 분포 `5점 398 / 4점 33 / 3점 9 / 2점 2 /

  - 최신순 메뉴를 불안정하게 조작하는 대신 전체 443개를 끝까지 검사한 뒤 작성일로

  - 원본 분포를 모두 확인한 후 별점별 최대 100개, 총 145개를 분석에 반영
  - 보고서의 별점별 원본 수와 분석 수가 분리되어 표시되는 것 확인
- `m.brand.naver.com/doodoostory/products/11256690153`
  - 네이버 화면에서 원본 리뷰 106개와 별점 분포 `5점 100 / 4점 4 / 3점 2 /
    2점 0 / 1점 0` 확인
  - 과거 확장 버전에서 일부 리뷰만 수집한 회귀가 있었으므로 P0-1 고정 검증 대상으로
    유지

확장 0.1.24부터 네이버 페이지 유형과 상품 ID를 안전한 진단 정보에 기록한다. 전체

다르면 `naver_source_total_mismatch`로 보고서 생성을 중단한다. 모바일 브랜드스토어,
스마트스토어, 쇼핑 카탈로그 URL 유형도 별도 회귀 테스트로 고정했다.

### 2026-08-09 자동 회귀 게이트와 실제 canary

- 실제 모바일 전체 리뷰 구조를 축약한 공유 fixture를 추가했다.
- Safari 확장과 중앙 collector가 같은 fixture에서 전체 목록, 별점 분포, 별점별 추출,
  최신순, 작성일과 `더보기 이미지 펼치기` 본문 정제를 함께 검사한다.
- 모든 push와 pull request 및 웹·Worker 배포 전에 `npm run release:gate`가 전체 테스트,
  Worker 타입 검사, collector 빌드를 실행한다. 하나라도 실패하면 배포 단계가
  시작되지 않는다.
- 실제 네이버 canary는 `m.brand.naver.com/doodoostory/products/9083360112` 한 상품을
  주 1회 별도 workflow에서 실행한다.
- 실제 canary는 전체 목록 여부, 최소 리뷰 수, 별점 1~5, 작성일 비율, 최신순, 중복과
  본문 오염을 검사한다.
- CAPTCHA, 로그인 요구, 접근 제한은 자동 우회하거나 재시도하지 않고 `blocked`로
  종료한다.
- 실제 Chrome canary는 iPhone Safari 실기기 검증을 대체하지 않으며, 일시적 사이트
  응답 문제와 코드 회귀를 구분해 운영자가 확인한다.

최초 로컬 검증에서는 격리된 새 Chrome 프로필로 위 상품을 정확히 한 번 열었다. 네이버
시스템 오류 계열 응답이 감지되어 `operator_required` / `blocked` / 종료 코드 `2`로
즉시 끝났으며, 자동 재시도나 우회는 수행하지 않았다. 이는 iPhone Safari에서 확인한
수집 성공과 별개로, 신규 데스크톱 Chrome 세션의 현재 접근성이 제한될 수 있음을
보여준다.
